# Epic 0 — Foundation

## Goal

A running skeleton: `docker compose up` brings up backend + frontend + Postgres + Redis, and a
consultant can create a Project through the UI and see it persisted. No AI, no meetings yet — this
epic exists purely to make every later epic buildable on a consistent base.

## Dependencies

Nothing. This is the first epic; all others depend on it.

## Key decisions (this epic)

- Docker Compose starts with only `postgres`, `redis`, `backend`, `frontend`. `worker` (Arq) is
  added in Epic 1; `qdrant` and `minio` in Epic 6 — each service arrives when a phase first needs
  it (addendum: service introduction timing).
- Backend managed with `uv`; frontend with `npm`.
- Domain-first architecture from day one: API routes stay thin → Application Service → Domain
  (Idea.MD §81, Architecture Principle 1).

## Stories

### Story 0.1 — Repository & tooling skeleton
**As** the builder, **I want** the repository laid out per the agreed structure with tooling
configured, **so that** every later epic has a predictable place for its code.

**Acceptance criteria:**
- Top-level directories exist: `backend/`, `frontend/`, `infrastructure/`, `docs/` (Idea.MD §58).
- Backend is `uv`-managed — `uv sync` succeeds against `backend/pyproject.toml`.
- Frontend is `npm`-managed — `npm install` succeeds against `frontend/package.json`.
- Python linters (ruff, black) and frontend linters (ESLint, Prettier, TS strict) are configured
  and pass on the empty skeleton (Idea.MD §80).

**Tasks:**
- [ ] Create the top-level directory tree per Idea.MD §58.
- [ ] Initialize `backend/pyproject.toml` with `uv`; declare fastapi, uvicorn, pydantic,
      pydantic-settings, sqlalchemy, alembic, asyncpg; dev-deps ruff, black, pytest.
- [ ] Configure ruff + black in `pyproject.toml`.
- [ ] Scaffold `frontend/` (Vite React + TS); add Tailwind, ESLint, Prettier; enable `strict` in
      `tsconfig.json`.
- [ ] Add `.gitignore` for Python + Node artifacts and local env files.
- [ ] Tests: verify `ruff check`, `black --check`, and `npm run lint` all pass on the skeleton.

### Story 0.2 — Backend application skeleton
**As** the builder, **I want** a FastAPI app with config, structured logging, and a health check,
**so that** the service boots and is observable from the start.

**Acceptance criteria:**
- `app/main.py` boots a FastAPI app with no startup error.
- `core/config.py` reads settings from `.env` via Pydantic Settings; a missing required setting
  fails fast with a clear error rather than a silent default.
- `core/logging.py` emits structured (JSON) logs, wired at startup (NFR4 / Idea.MD §77).
- `GET /health` returns 200 with a small JSON body.

**Tasks:**
- [ ] Create the `app/` package layout (`api/v1`, `core`, `db`, `domain`) per Idea.MD §58.
- [ ] Implement `core/config.py` Settings (env-driven, typed).
- [ ] Implement `core/logging.py` JSON logging and initialize it on app startup.
- [ ] Implement the `/health` endpoint.
- [ ] Add a uvicorn run entry (and a `make` target) for local run.
- [ ] Tests: `/health` returns 200; config raises on a missing required var.

### Story 0.3 — Database foundation
**As** the builder, **I want** an async SQLAlchemy engine/session and Alembic migrations wired up,
**so that** domain models can be persisted and evolved safely.

**Acceptance criteria:**
- `db/database.py` exposes an async SQLAlchemy 2.0 engine and a session dependency.
- `alembic upgrade head` runs against Postgres with no error.
- A trivial migration can be autogenerated, applied, and rolled back (round-trips cleanly).

**Tasks:**
- [ ] Add the async engine (asyncpg) and `AsyncSession` factory in `db/database.py`.
- [ ] Provide a FastAPI session dependency.
- [ ] Initialize Alembic; wire `env.py` to the settings DB URL in async mode.
- [ ] Verify autogenerate + upgrade/downgrade on a throwaway table.
- [ ] Tests: a connectivity test opens a session and runs `SELECT 1`.

### Story 0.4 — Project domain
**As** a consultant, **I want** a Project to be a first-class persisted entity, **so that** every
client engagement has a container.

**Acceptance criteria:**
- `Project` SQLAlchemy model with a status enum (`DISCOVERY` → … → `COMPLETED`, Idea.MD §8) and
  created/updated timestamps.
- A first Alembic migration creates the `projects` table.
- `ProjectCreate` / `ProjectRead` Pydantic schemas exist.
- `domain/projects/service.py` holds create/list/get logic; routes never touch the ORM directly
  (Idea.MD §81).

**Tasks:**
- [ ] Define the `ProjectStatus` enum (Idea.MD §8).
- [ ] Define the `Project` model (id, name, description, status, timestamps).
- [ ] Generate and apply the `projects` migration.
- [ ] Define `ProjectCreate` and `ProjectRead` schemas.
- [ ] Implement `domain/projects/service.py` (`create`, `list`, `get`).
- [ ] Tests: service unit tests — create persists, list returns, get by id, get-missing raises
      not-found.

### Story 0.5 — Project API
**As** a consultant, **I want** REST endpoints to create, list, and get Projects, **so that** the
frontend can manage them.

**Acceptance criteria:**
- `POST /api/v1/projects` creates a Project and returns it (201).
- `GET /api/v1/projects` lists Projects.
- `GET /api/v1/projects/{id}` returns one Project; an unknown id returns 404.
- All three appear in the OpenAPI docs and delegate to the application service.

**Tasks:**
- [ ] Implement `api/v1/projects.py` routes delegating to `domain/projects/service.py`.
- [ ] Register the router under `/api/v1`.
- [ ] Add request validation and 404 handling for unknown ids.
- [ ] Tests: API tests for create / list / get, plus 404 on an unknown id.

### Story 0.6 — Frontend foundation
**As** the builder, **I want** a React + TypeScript app scaffolded with the agreed UI stack, **so
that** pages can be built consistently.

**Acceptance criteria:**
- Vite + React 18 + TypeScript + Tailwind + shadcn/ui builds and runs (`npm run dev`).
- A React Query provider is configured at the app root.
- A typed API client/service layer targets the backend base URL from env.
- The frontend test runner is configured with at least one passing test.

**Tasks:**
- [ ] Add and theme Tailwind + shadcn/ui.
- [ ] Configure the React Query provider at the app root.
- [ ] Create an API client (base URL from env) and a `projects` service (list/create/get).
- [ ] Set up the test runner (e.g. Vitest) + one smoke test.
- [ ] Tests: a render smoke test passes.

### Story 0.7 — Project workspace shell
**As** a consultant, **I want** to see my Projects and create a new one from the UI, **so that** I
can start an engagement. *(Partial FR-20 — the workspace shell; full cross-phase status is Epic 9.)*

**Acceptance criteria:**
- A Project list view renders Projects from `GET /api/v1/projects`.
- A create-Project form persists a Project and it appears in the list without a full page reload.
- The workspace shell shows nav for Overview/Meetings/Intelligence/MVP/Design/Development/QA/Demo
  (Idea.MD §38); later tabs may be placeholders.
- An empty state is shown when there are no Projects; API errors surface a message rather than a
  blank screen.

**Tasks:**
- [ ] Build the Projects list page (React Query `useQuery`).
- [ ] Build the create-Project form (`useMutation` + cache invalidation).
- [ ] Build the workspace shell layout with nav tabs (placeholders allowed).
- [ ] Handle loading, empty, and error states.
- [ ] Tests: list renders; create flow adds a row (against a mocked API).

### Story 0.8 — Local dev orchestration
**As** the builder, **I want** one command to bring the stack up, **so that** onboarding and daily
work are frictionless.

**Acceptance criteria:**
- `docker-compose.yml` defines `postgres`, `redis`, `backend`, `frontend` (no worker/qdrant/minio
  yet).
- `docker compose up` starts all four; the backend answers `/health` 200 and the frontend is
  served.
- `.env.example` is accurate and no secrets are committed.
- `Makefile` provides `up` / `down` / `migrate` / `test`; `README.md` documents local dev setup.

**Tasks:**
- [ ] Write Dockerfiles for backend and frontend.
- [ ] Write `docker-compose.yml` (postgres, redis, backend, frontend) with healthchecks.
- [ ] Create `.env.example` matching `core/config.py` and the compose file.
- [ ] Write `Makefile` targets `up` / `down` / `migrate` / `test`.
- [ ] Write the README local-dev section.
- [ ] Tests: confirm `docker compose up` reaches `/health` 200 from a clean checkout.

### Story 0.9 — Test scaffolding
**As** the builder, **I want** a working test harness, **so that** later epics inherit a place for
tests.

**Acceptance criteria:**
- Backend pytest runs via `make test` with at least one passing test.
- The frontend test runner runs via an npm script with at least one passing test.
- Tests exit with CI-friendly status codes on a clean checkout.

**Tasks:**
- [ ] Configure pytest (`conftest.py`, async test support, test DB/fixtures).
- [ ] Add a backend smoke test (e.g. `/health`).
- [ ] Wire the frontend test script + a smoke test.
- [ ] Make `make test` run the backend suite (and document the frontend command).
- [ ] Tests: the scaffolding itself is green on a clean checkout.

## Epic Definition of Done

- `docker compose up` starts every service successfully (Idea.MD §61 acceptance).
- A Project can be created via the UI and is persisted in Postgres.
- `/health` returns 200.
- Tests pass.
- No secrets committed; `.env.example` accurate.
- Standing rules honored (see [index.md](index.md) — "Standing rules, every epic").
